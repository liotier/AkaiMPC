# 00 - Catalogue snapshot: a reviewable record of what every template produces

| | |
|---|---|
| Status | implemented |
| Type | tooling |
| Size | S |
| Depends on | nothing |
| Blocks | every other spec's acceptance section |
| Recommended model | Claude Haiku 5.5 (`claude-haiku-5-5`); the format below is complete and the two existing tools show the pattern |

## 1. Problem

`tools/audit-theory.mjs` checks that each pad is internally consistent: its
notes contain the pitch classes its type requires, its name matches its type,
its roman numeral matches its root and quality. It passed while twelve
templates played leading-tone major triads where their nicknames promise
subtonic chords (spec 02), and it will pass equally well after any of the
other specs changes what those templates produce. Internal consistency is
necessary and not sufficient: nothing records *what the catalogue sounds
like*, so no change to it can be reviewed by reading a diff.

The pack is byte-identical across builds, which makes it a good regression
test for "nothing changed" and a useless one for "the right thing changed" -
a zip hash does not say which chord moved.

## 2. Decisions

| # | Decision | Rationale |
|---|---|---|
| D1 | The snapshot is a **committed text file** in `docs/`, regenerated by a tool and checked in CI. | A diff in a pull request is the review artefact. Nothing else in the project lets a human read a theory change. |
| D2 | It records **chord names and roman numerals**, not MIDI notes, for every pad of the Classic and Jazz variants. | Chord content is what the specs change. Voicings are covered by the pack's determinism, with one exception in D4. |
| D3 | Major-tonality templates are rendered in **C**, minor-tonality templates in **A**. | Chord names then carry no accidentals in the diatonic case, so a diff reads as music, not as enharmonics. |
| D4 | One voicing line per template: the **Smooth** variant's row-1 MIDI notes. | Smooth is the only style with a search behind it; a regression there (such as the dropped chord tones of `../mpc-export-specification.md` §7.1) should show in a diff. Four pads suffice to catch it. |
| D5 | Scale Mode is included: one block per scale, 16 pads. | Cheap, and the scale-derived harmony has its own history of defects. |
| D6 | The tool has exactly two modes, `--write` and `--check`; `--check` is what CI runs. | Same contract as a formatter. |

## 3. Normative specification

### 3.1 Tool

`tools/catalogue-snapshot.mjs`, an ES module runnable under Node 20+ like the
two existing tools, importing only from `../modules/` and
`../locales/en.json`. No DOM.

```
node tools/catalogue-snapshot.mjs --write    # regenerate docs/catalogue-snapshot.txt
node tools/catalogue-snapshot.mjs --check    # exit 1 if a regeneration would differ
```

With no flag, print usage and exit 2. `--check` prints the first 40 lines of
a unified diff on failure and the sentence "Run with --write and commit the
result if the change is intended."

### 3.2 Tonality of a template

Until spec 07 adds an explicit `tonality` field, derive it:

- find the first token whose degree is I (stem `I` or `i`, no `/`, any suffix);
- lower case means `minor`, upper case means `major`;
- no such token means `major`.

When `template.tonality` exists, it wins over the derivation. The nine
templates with no tonic token are listed in spec 07 §3.1 with their intended
tonality; until 07 lands they render in C.

### 3.3 Output format

Plain UTF-8, LF line endings, one trailing newline, no tabs. Deterministic:
iterate `progressions` in object order, then templates in array order, then
`modes` in object order. Exactly this layout; the pad contents shown are illustrative, not measured:

```
# Catalogue snapshot. Generated by tools/catalogue-snapshot.mjs - do not edit by hand.
# Templates: Classic and Jazz variants, in C for major tonality, in A for minor.
# A leading * marks a progression chord. Smooth voicings are MIDI note numbers.

## Pop/Rock | I—V—vi—IV | Axis of Awesome | major | C
Classic  1-4   *C [I]  *G [V]  *Am [vi]  *F [IV]
Classic  5-8   Dm7 [ii7]  C7 [I7]  ...
Classic  9-12  ...
Classic 13-16  ...
Jazz     1-4   ...
Jazz     5-8   ...
Jazz     9-12  ...
Jazz    13-16  ...
Smooth   1-4   60,64,67 | 59,62,67 | 57,60,64 | 57,60,65

## Scale | Dorian | Common Western Tonal | C
Pads     1-4   Cm [i]  Dm [ii]  Eb [III]  F [IV]
Pads     5-8   ...
Pads     9-12  ...
Pads    13-16  ...
```

Pads within a line are separated by two spaces; a pad is `name [numeral]`,
with `*` prefixed when `isProgressionChord` is true. The nickname is the
English one from `locales/en.json`. Blocks are separated by one blank line.

### 3.4 CI

Add a step to `.github/workflows/check-theory.yml` after the audit:

```yaml
      - name: Check the catalogue snapshot
        working-directory: AkaiMPCChordProgressionGenerator
        run: node tools/catalogue-snapshot.mjs --check
```

and add `AkaiMPCChordProgressionGenerator/docs/catalogue-snapshot.txt` to the
workflow's `push.paths` so a hand edit of the snapshot also triggers the job.

### 3.5 Documentation

- `README.md` of the generator, section "Under the Hood": one bullet naming
  the tool and the rule that a theory change ships with its snapshot diff.
- `../mpc-export-specification.md` §7.13: one sentence pointing here as the
  complement of the audit. Do not rewrite §7.

## 5. Acceptance

1. `--write` then `--check` passes; a second `--write` produces a
   byte-identical file.
2. The file has one block per template entry (173 at baseline, so a value
   listed under two genres appears twice, under each) and one per scale (34).
3. Changing one chord type in one template and re-running `--check` fails and
   prints a diff naming that template's block.
4. The CI job fails on a snapshot that is out of date and passes once
   regenerated.
5. Measured and recorded in the PR: line count of the snapshot and the run
   time of `--check` (expect well under five seconds; the pack build measures
   316 ms for 839 variants).

## 6. Out of scope

- Snapshotting all five styles. Voicing differences are the pack's job.
- Snapshotting every key. The twelve keys are a transposition; the audit
  already covers enharmonic spelling across them.

## 7. Implementation notes

Implemented as specified, with the additions below and one departure.

- **A diff helper.** `--check` has to print a unified diff, the project has no
  dependencies and no guarantee of diff(1), so `tools/lib/unified-diff.mjs`
  writes one. This is the departure from "importing only from `../modules/` and
  `../locales/en.json`": it is a sibling helper, the pattern `build-pack.mjs`
  already uses for `tools/lib/zip.mjs`. Tested against GNU `patch` on 400 random
  pairs: every diff applied and reproduced its target, and each had the same
  number of changed lines as `diff --minimal`.
- **The category is passed to the engine already.** `generateVariant()` ignores
  it until spec 01 lands, so until then the blocks of a value listed under
  several genres are identical, and they start to differ the moment the engine
  reads the category.
- **A hunk names its block.** The header of each hunk quotes the nearest `## `
  line above its first change, as git does with function names, so a change deep
  inside a block still names the template. Before the diff, `--check` lists up to
  ten changed, added or removed blocks.
- **Plain failures.** A CRLF checkout and a missing final newline each get their
  own message instead of a diff that marks every line. A template with no English
  nickname, a duplicate block header and a variant that is not a complete
  sixteen-pad grid stop the run with an error rather than a quiet fallback.
- **The workflow also watches the tool.** `tools/catalogue-snapshot.mjs` is in
  `push.paths` beside the snapshot file, as the other two tools are. The
  generator README also lists the tool in its file layout, beside the one bullet
  the spec asked for.

Measured when it was introduced, on commit `0593d6d` plus the specs: 2 110 lines,
114 KB, 173 template blocks (68 minor, 105 major, of which nine have no tonic
token) and 34 scale blocks; `--check` takes about 0.2 s.

Not specified, found on the first day: the snapshot made the Jazz variant's
doubled numeral suffixes visible (`i99`, `Isus4sus4`, `vii°ø7`). Spec 05 now
describes them and carries the fix.
